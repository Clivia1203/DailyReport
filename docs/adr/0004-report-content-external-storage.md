# 报告正文与思考过程外置，保留 JSON 兼容迁移

## 状态

已接受

## 背景

`data.json` 同时保存日报记录、周期报告元数据、完整报告正文和 AI 思考过程。报告正文和思考过程属于体积较大的附属内容，频繁编辑或保存时会让整个 JSON 文件反复重写；一旦 JSON 写入中断，也会让所有本地数据都受到影响。与此同时，已有版本已经把报告正文以内嵌字段写入 `data.json`，不能要求用户手工迁移。

## 决策

- `data.json` 继续作为本地数据索引，保存记录、报告元数据以及外置附件的文件名。
- 每份周期报告的正文保存为 `reports/<报告标识>.md`；存在 AI 思考过程时保存为 `reports/<报告标识>.thinking.json`。
- 读取时优先使用外置附件，附件不存在或不可读时回退到旧版内嵌的 `content` / `thinking` 字段，保证老数据可读。
- 应用启动读取数据库后，自动把旧版内嵌正文和思考过程迁移为外置附件，再以原子方式更新 `data.json`。迁移失败时保留旧字段并在下次启动重试。
- 发送给渲染层和导出备份时恢复完整正文与思考过程，不暴露内部文件路径；备份恢复仍经过内嵌格式过渡，因此不改变备份格式。
- `data.json` 每次替换前保留上一份有效文件为 `data.json.bak`。主文件损坏时先把损坏现场复制到 `backups`，再尝试恢复上一份有效文件。

## 后果

这种切入点把“报告附属内容的读写”收进独立的报告存储模块，主进程和渲染层继续使用原有报告接口，改动局部且便于后续替换实现。新版本的 JSON 更小、普通记录保存不需要携带完整报告正文；代价是每份报告会多一个或两个本地附件文件，需要在备份和恢复时同时处理。

SQLite 暂不作为当前实现：现有数据量和查询模式不需要引入数据库依赖，先解决大字段重写与 JSON 损坏恢复；未来若出现复杂查询、并发写入或数据规模明显增长，可以在该存储模块后面替换实现，而不改变上层接口。
