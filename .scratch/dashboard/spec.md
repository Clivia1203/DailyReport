# Spec: 界面看板化优化（dashboard）

Status: ready-for-agent

## Problem Statement

主界面是纯功能堆叠（录入框→导出框→筛选栏→列表），打开软件看不到"今天记了几条、最近记录频率如何"这类一眼可得的概览，缺乏看板感；界面视觉重心缺失，显得简陋。

## Solution

在保持现有单列布局与操作习惯不变的前提下，新增三个模块并做一轮细节打磨：常驻统计条（今日/本周/累计三卡，可点击聚焦列表）、近 14 天活动柱状图（可点击聚焦到某天）、录入区上方的今日面板（问候语+日期）。引入"范围聚焦"交互模型：统计卡与活动图柱子都能把列表限定到对应日期范围，以范围芯片呈现，与既有年/月下拉互斥。

## User Stories

1. 作为用户，我想打开主界面就看到今日、本周、累计的记录数，以便一眼掌握自己的记录情况
2. 作为用户，我想点击"今日"卡片让列表只显示今天的记录，以便快速回顾今天做了什么
3. 作为用户，我想点击"本周"卡片只看本周记录，以便整理周报素材
4. 作为用户，我想点击"累计"卡片清除所有日期筛选回到全量视图
5. 作为用户，我想在范围聚焦激活时看到范围芯片（如"本周 ×"），以便理解当前列表为什么只有这些内容
6. 作为用户，我想点芯片上的 × 或再点一次统计卡来取消聚焦
7. 作为用户，当我改用年/月下拉筛选时，我希望范围聚焦自动取消，避免"本周 ∩ 2026年"这种看不懂的组合
8. 作为用户，当我点统计卡聚焦时，我希望年/月下拉自动复位为"全部"，理由同上
9. 作为用户，我想搜索框在任何筛选状态下都可用且与之叠加，以便在任意范围内找内容
10. 作为用户，我想看到近 14 天的活动柱状图，以便直观了解自己最近的记录频率
11. 作为用户，我想悬停柱子看到"日期 + N 条"的提示
12. 作为用户，我想点击某天的柱子把列表聚焦到那一天
13. 作为用户，我想让今天的柱子高亮显示，以便一眼看出今天是否还没记录
14. 作为用户，在没有任何记录的日子我想看到浅色底座柱，让图表不显得残缺
15. 作为用户，我想在录入区上方看到问候语和日期，让打开软件有"开始今天"的仪式感
16. 作为用户，我想让统计条、活动图、今日面板在浅色和深色主题下都正确适配
17. 作为用户，我想在新增、编辑、删除记录后统计数字和活动图立即刷新
18. 作为用户，在数据库为空时我想看到归零的统计、全底座的图表和友好的空状态，而不是报错或空白

## Implementation Decisions

- **统计模块（新增，渲染层纯函数）**：导出 `statsFor`（今日/本周/累计三数字）、`weekStart`（本周周一零点）、`dayCounts`（近 N 天逐日计数）、`filterByRange`（范围筛选）。这是全部数据逻辑的收口处，也是唯一测试接缝。
- **"本周"口径**：周一 00:00 至周日 23:59 的自然周（见 CONTEXT.md）。
- **范围模型**：`{ type: 'day' | 'week' | 'all' }`；`all` 即清除日期筛选。范围聚焦与年/月下拉互斥（激活一方自动复位另一方），关键词搜索与两者叠加（ADR-0003）。
- **活动图**：纯 CSS/SVG 柱状实现，不引入图表库；固定 14 天窗口；今天主色高亮；0 条渲染底座柱；hover 显示自绘轻量提示（日期+条数）。
- **布局**：统计条与今日面板固定常驻；活动图作为列表滚动区的首个元素随列表滚动。
- **今日面板**：问候语五段切分——5-11 早上好 / 11-13 中午好 / 13-18 下午好 / 18-23 晚上好 / 23-5 夜深了，另附日期与星期。
- **视觉**：沿用描边分层扁平基调（ADR-0002），主按钮保持纯色不用渐变；主题沿用主进程单一数据源（ADR-0001）。
- **刷新**：每次记录集合变化（增删改）即全量重算统计与图表，数据量级下无需缓存。

## Testing Decisions

- 只测统计模块纯函数的**外部行为**（数据进、数据出），不测 DOM 结构与实现细节；界面层沿用既定的截图验收流程。
- 测试运行器用 Node 内置 `node --test`，零新增依赖。
- 必测边界：周一边界（本周第一天/最后一天）、跨年的周、空库、当天 0 点前后、"day 聚焦 + 搜索叠加"的计数、互斥复位逻辑的数据侧。
- 本项目无先例测试，本 spec 的测试将成为仓库首批，为后续树立范式。

## Out of Scope

- 连续记录天数统计（已明确否决）
- GitHub 式热力图形态
- 渐变按钮、任何投影回归
- 图表库引入
- 列表布局重构（侧边导航等）
- 导出功能变更
