# Spec: 响应式布局与录入/导出收纳（responsive-layout）

Status: ready-for-agent

## Problem Statement

窄窗口下录入卡与导出卡常驻，堆叠内容太多显得拥挤；大窗口只是把窄布局放大（内容仍限宽单列），控件密集、空间利用差，观感局促。

## Solution

- **窄窗口（<1200px）**：录入卡默认收起，工具栏"＋ 记一笔"按钮触发内联展开（自动聚焦，Esc/再点/保存后收起，快捷键 Ctrl+N）；导出改为工具栏按钮 → 居中模态对话框（Esc/遮罩/取消关闭）。今日面板与统计条保留常驻。
- **宽窗口（≥1200px）**：双栏布局——左主列（工具栏+活动图+列表），右侧栏（今日面板+统计纵排+**常驻录入卡**）；导出按钮同样走模态。用空间解决"挤"。

## User Stories

1. 作为用户，窄窗口下我想让界面默认更清爽，录入和导出按需展开
2. 作为用户，我想点"＋ 记一笔"立即在统计条下方展开录入卡并聚焦输入框
3. 作为用户，我想用 Ctrl+N 快捷键唤起录入
4. 作为用户，保存成功后录入卡自动收起，列表立即可见新记录
5. 作为用户，我想用 Esc 或再点按钮收起录入卡
6. 作为用户，我想点"导出"按钮弹出居中对话框完成导出，Esc/遮罩/取消可关闭
7. 作为用户，大窗口下我想看到双栏布局：右侧常驻录入和统计，左侧专心看列表
8. 作为用户，拖动窗口大小跨过断点时布局平滑切换，不丢功能

## Implementation Decisions

- 断点 1200px（CSS media query 驱动可见性；JS 只管理"用户手动开合"意图与聚焦）
- 录入开合状态仅窄屏生效；宽屏 CSS 强制常驻（.open 有无无关）
- 导出控件整体迁入模态；保存路径仍用系统对话框
- 统计条宽屏改纵排卡片；窄屏维持横排
- 无新增数据逻辑；stats.js 接缝不变，测试维持 16 例

## Testing Decisions

- 纯函数无新增，`npm test` 保持全绿
- 界面走真机 AX 树 + 截图验收：窄窗口（默认 1000px）与宽窗口（外力调整至 1300px）两种形态

## Out of Scope

- 快速记录条（全局热键那条）不动
- 列表虚拟滚动等性能优化
